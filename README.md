# СтройРадар — мониторинг стройплощадки (ТЗ ДГП Москвы)

Прототип ищет расхождения между календарным планом строительно-монтажных работ и тем, что видно на снимках с камер. Модель распознаёт строительную технику, снимки одной даты сводятся в состав машин, этот состав сравнивается с плановым этапом. Если техники нужного этапа нет или звено неполное, система показывает отклонение с зоной из плана и ссылками на кадры.

В интерфейсе продукт называется **СтройРадар**.

## Обязательные функции (ТЗ)

1. Обнаружение и классификация техники (YOLOv8, 12 классов).
2. Сопоставление с графиком по методике «этап работ → необходимая техника».
3. Визуализация в веб-интерфейсе.
4. Отклонения: нет нужной техники, неполное звено, техника другого этапа — с зоной и снимками-подтверждениями.

Пример из ТЗ закрыт методикой и тестом `test_incomplete_link_like_tz_example`: на этапе «Откопка котлована» виден экскаватор и нет самосвалов или грузовиков. Система предупреждает о возможном снижении темпа работ.

## Методика «этап → необходимая техника»

Источник правил — `backend/domain/stages.py` и `backend/domain/rules.py`. Страница «О продукте» показывает тот же каталог, который отдаёт `GET /api/stages`.

Две сущности:

- **Маркер** — машина, по которой этап опознаётся. Достаточно одной машины из списка маркеров.
- **Звено** — машины, без которых работа на этом этапе не идёт. Звено записано группами: внутри группы хватает любой машины, все группы должны быть закрыты одновременно.

Единица сопоставления — **сутки**. Все кадры с одной датой `captured_at` складываются в один набор детекций, затем считается количество машин по классам. Плановый этап — строка календаря, в чей интервал `date_from`…`date_to` попадает эта дата. Если на дату попадает несколько строк, основной этап — первая подходящая в файле плана. Статус объекта на карте — худший статус среди дней, где есть снимки.

Количество — это число рамок на кадрах суток, без трекинга: одна машина на пяти кадрах учитывается пять раз. Для проверки «техника была на площадке» этого достаточно, для учёта машино-часов — нет.

### Этапы

Порядок ниже — хронология строительства. По кадру этап выбирается иначе: берётся более узкий сигнал, см. следующий раздел.

| Код | Этап | Маркер (достаточно одного) | Звено |
|---|---|---|---|
| `clearing` | Расчистка участка | бульдозер или погрузчик | самосвал или грузовик |
| `excavation` | Откопка котлована | экскаватор | самосвал или грузовик |
| `foundations` | Устройство фундаментов | сваебой | автокран или кран-манипулятор |
| `frame` | Монтаж каркаса, стены и перекрытия | башенный кран, бетономешалка или бетононасос | бетономешалка и бетононасос |
| `landscaping` | Благоустройство | каток | не требуется |

Звено каркаса проверяется только если на снимках суток уже есть бетономешалка или бетононасос. Башенный кран без бетонной техники этап закрывает сам. Если бетонная техника появилась, нужны обе машины: насос без миксера и миксер без насоса — неполное звено.

Погрузчик на благоустройстве отмечен в каталоге как необязательный (`optional`). На расчёт отклонений это поле не влияет.

### Как по технике выбирается фактический этап

Если на снимках машины разных этапов, главный факт — первый подходящий пункт:

1. Сваебой → устройство фундаментов.
2. Каток → благоустройство, если рядом нет экскаватора и бульдозера. Вместе с ними каток ещё не означает благоустройство.
3. Башенный кран, бетономешалка или бетононасос → монтаж каркаса.
4. Экскаватор → откопка котлована. Бульдозер рядом с экскаватором остаётся котлованом и не открывает расчистку.
5. Бульдозер или погрузчик → расчистка участка.

Самосвал, грузовик, автокран и кран-манипулятор этап сами не открывают (`SUPPORT_ONLY`). Иначе проезжающий самосвал переводил бы площадку в земляные работы.

### Отклонения и статусы

| Тип | Когда | Статус дня |
|---|---|---|
| `incomplete_link` | Маркер этапа есть, звено не закрыто | `idle` — простой |
| `missing_required` | По плану этап идёт, маркерной техники нет | `warning` — возможное нарушение |
| `unexpected_equipment` | Главный факт по технике — другой этап, чем в плане | `info` — опережение графика |
| нет отклонений | Маркер и звено на месте | `ok` — в норме |
| нет кадров | За день нет снимков | `no_data` — нет данных |

У отклонения есть готовая формулировка, зона из колонки плана и список `photo_ids`. Предупреждение можно открыть на конкретных кадрах.

Приоритет статуса объекта, от худшего: простой, возможное нарушение, опережение графика, норма, нет данных.

### Календарный план

CSV или Excel. Колонки, регистр заголовка не важен:

| Смысл | Заголовки |
|---|---|
| Этап | `stage`, `этап`, `stage_code`, `код`, `name`, `название` |
| Начало | `date_from`, `начало`, `from`, `start`, `date_start` |
| Конец | `date_to`, `конец`, `to`, `end`, `date_end` |
| Зона | `zone`, `зона`, `участок` — необязательно |

Коды этапов: `clearing`, `excavation`, `foundations`, `frame`, `landscaping`. Принимаются и русские названия: «расчистка», «котлован», «земляные работы», «фундаменты», «сваи», «каркас», «монолит», «монтаж», «надземная часть», «благоустройство». Старые коды из ранних планов тоже читаются: `earthworks` → котлован, `piling` → фундаменты, `monolith` и `superstructure` → каркас.

## Классы модели (12)

Порядок id для дообучения:

0 excavator, 1 bulldozer, 2 loader, 3 dump_truck, 4 concrete_mixer, 5 concrete_pump, 6 tower_crane, 7 autocrane, 8 pile_driver, 9 roller, 10 crane_manipulator, 11 truck.

| Код | Как в интерфейсе |
|---|---|
| `excavator` | Экскаватор |
| `bulldozer` | Бульдозер |
| `loader` | Погрузчик |
| `dump_truck` | Самосвал |
| `concrete_mixer` | Бетономешалка |
| `concrete_pump` | Бетононасос |
| `tower_crane` | Башенный кран |
| `autocrane` | Автокран |
| `pile_driver` | Сваебой |
| `roller` | Каток |
| `crane_manipulator` | Кран-манипулятор |
| `truck` | Грузовик |

Перечень ТЗ (самосвал, экскаватор, каток, кран-манипулятор, бетоносмеситель, бульдозер, грузовик, автокран) покрыт полностью. Погрузчик, бетононасос, башенный кран и сваебой добавлены сверх него: без них не разделить расчистку, фундаменты, каркас и благоустройство.

Текущая модель: YOLOv8m, 100 эпох, imgsz 640. Precision 0.821, Recall 0.832, mAP@50 0.859, mAP@50-95 0.651. Кривые и матрицы ошибок — в `ml/runs/detect/ml_v2/`. Порог уверенности задан на класс в `ml/classes.py`: слабые классы не отсекаются общим порогом детектора.

## Структура

```
backend/     FastAPI: detect, sites, timeline, /api/demo/analyze
  domain/    бизнес-логика: этапы, правила отклонений, статусы
frontend/    Vite + React: дашборд, демо, объект, снимок, методика
ml/          инференс + classes (12) + метрики обучения в runs/detect/ml_v2
scripts/     веса, проверочный набор, сборка документов, датасет
docs/        документация, презентация, отчёт о тестировании
data/        store.json, photos/ (рабочие данные рантайма)
Демо/        пакет: ИНСТРУКЦИЯ.txt, график/, фото/, кадры для теста модели
```

## Запуск через Docker

```powershell
docker compose up --build
```

Файл модели `ml/weights/best.pt` уже лежит в проекте. Если его нет, верните его командой `py -m scripts.fetch_weights` и запустите Docker ещё раз.

Интерфейс: http://127.0.0.1:5173, API: http://127.0.0.1:8000/docs.
Веса и `data/` монтируются с хоста, поэтому пересборка образа их не теряет.

## Локальный запуск

### Веса модели

Файл весов `ml/weights/best.pt`, около 50 МБ, лежит в проекте. Если его удалили, верните так:

```powershell
py -m scripts.fetch_weights
```

Скрипт кладёт `best.pt` в `ml/weights/`, распаковывает метрики обучения и проверяет, что модель знает все 12 классов. Если весов нет, backend поднимется на предобученном `yolov8n` и `/api/health` вернёт `"status":"degraded"`.

### Backend (порт 8000)

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
uvicorn backend.main:app --reload --host 127.0.0.1 --port 8000
```

### Frontend (порт 5173)

```powershell
cd frontend
npm install
npm run dev
```

Открыть: http://127.0.0.1:5173.

## Демо-сценарий

1. Открыть вкладку **Демо**.
2. Нажать «Загрузить демо-данные» — график и 15 кадров подставятся из `Демо`.
3. «Запустить анализ» → детекции, таймлайн план/факт, замеры скорости. Предупреждение за день открывается кнопкой «Открыть».

Свои данные грузятся в те же два поля: план (CSV или Excel) и произвольное число снимков.

## Проверка

```powershell
py -m pytest backend/test_rules.py -q   # методика сопоставления, без модели
py -m scripts.eval_model                # проверочный набор + замер скорости
```

`eval_model` раскладывает кадры по условиям съёмки (освещённость, сезон), прогоняет модель и пишет `docs/отчёт_тестирования.md`.
