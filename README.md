# Build Watch — мониторинг стройплощадки (ТЗ ДГП Москвы)

Прототип: детекция строительной техники на снимках с камер → сопоставление с календарным планом СМР → выявление отклонений.

## Обязательные функции (ТЗ)

1. Обнаружение и классификация техники (YOLO, 12 классов).
2. Сопоставление с графиком по методике «этап → необходимая техника».
3. Визуализация в веб-интерфейсе.
4. Отклонения: нет нужной техники, неполное звено, техника не под этап — с привязкой к снимкам и зоне.

## Структура

```
backend/     FastAPI: detect, sites, timeline, /api/demo/analyze
  domain/    бизнес-логика: этапы, правила отклонений, статусы
frontend/    Vite + React: дашборд, демо, объект, снимок, методика
ml/          инференс + classes (12) + метрики обучения в runs/detect/ml_v2

docs/        документация, презентация, отчёт о тестировании

```

## Запуск через Docker

```powershell
py -m scripts.fetch_weights
docker compose up --build
```

Интерфейс: http://127.0.0.1:5173, API: http://127.0.0.1:8000/docs.
Веса и `data/` монтируются с хоста, поэтому пересборка образа их не теряет.

## Локальный запуск

### Веса модели

Файл весов ~50 МБ и в git не хранится:

```powershell
py -m scripts.fetch_weights
```

Скрипт кладёт `best.pt` в `ml/weights/`, распаковывает метрики обучения и проверяет, что модель знает все 12 классов. Если весов нет, backend поднимется на предобученном `yolov8n` и `/api/health` вернёт `"status":"degraded"`.

### Backend (порт 8000)

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
uvicorn backend.main:app --reload --host 127.0.0.1 --port 8000
```

### Frontend (порт 5173)

```powershell
cd frontend
npm install
npm run dev
```

Открыть: http://127.0.0.1:5173.

## Демо-сценарий

1. Открыть вкладку **Демо**.
2. Нажать «Загрузить демо-данные» — план и пять кадров подставятся из `Демо_конкурс`.
3. «Запустить анализ» → детекции, таймлайн план/факт, предупреждения со ссылками на снимки, замеры скорости.

Свои данные грузятся в те же два поля: план (CSV или Excel) и произвольное число снимков.

## Проверка

```powershell
py -m pytest backend/test_rules.py -q   # методика сопоставления, без модели
py -m scripts.eval_model                # проверочный набор + замер скорости
```

`eval_model` раскладывает кадры по условиям съёмки (освещённость, сезон), прогоняет модель и пишет `docs/отчёт_тестирования.md`.

## Классы модели (12)

Порядок id для дообучения:  
0 excavator, 1 bulldozer, 2 loader, 3 dump_truck, 4 concrete_mixer, 5 concrete_pump,  
6 tower_crane, 7 autocrane, 8 pile_driver, **9 roller, 10 crane_manipulator, 11 truck**.

Текущая модель: YOLOv8m, 100 эпох, imgsz 640. Precision 0.821, Recall 0.832, mAP@50 0.859, mAP@50-95 0.651. Кривые и матрицы ошибок — в `ml/runs/detect/ml_v2/`.
